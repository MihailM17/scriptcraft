# ScriptCraft v0.7 — revision workflow plan

Status: M1, M2 and M3 complete 2026-10-21. Derived from `ScriptCraft_Vision_and_Roadmap.pdf` (2026-10-21)
and the locked decisions in `ROADMAP.md`.

## Why this is the next feature

The vision is strong, but the 90-day promise is trust, not platform breadth.
Working screenwriters need revision marks before they can replace Final Draft
or KIT Scenarist. Revision pages also force stable block identity, durable
project data, and a testable compatibility story — foundations the local API
and agent work need anyway.

Non-goals for v0.7: collaboration/CRDT, comments, plugin API, AI, a new native
file format, and production breakdowns.

      block-level baseline snapshots, deterministic diff.
- [x] Persist baselines as JSON in the `.kitsp` `scenario_data` row
      `scriptcraft_revisions`; KIT ignores unknown rows.
- [x] Keep the row inside the normal atomic save/recovery path.
- [x] Start Revision / Clear Revision History actions in the in-app menu and
      macOS Edit menu.
- [x] Paint a coloured margin bar on every changed block; status bar shows the
      active revision colour.
- [x] Unit tests for colour rollover, insert/delete, scene edits, reordering,
      and multi-revision override; round-trip test through `.kitsp`.
- [x] M1 stopped at editor marks; PDF/FDX output moved to M2.

Exit criteria: A writer can start Blue, edit, save, reopen, and see Blue marks;
start Pink, edit again, and see Blue + Pink with Pink overriding where the same
block changed twice. A95 and all existing tests stay green.

### M2 — Revision pages and export (complete 2026-10-21)

- [x] Revision-page mode (current revision only) in the editor and PDF.
- [x] PDF/FDX revision colours and `*` marks (FDX `<Revisions>` element).
- [x] `Start Revision` snapshots a page-count baseline and reports added pages.
- [x] Colour legend and revision list with names/dates.

### M3 — Production polish (complete 2026-10-21)

- [x] Locked pages/scenes with explicit unlock. Lock captures every page
      start as a content anchor (heading/cue/text, paragraph offset, optional
      `kit_uuid`, neighbouring context). Layout forces those starts; pages
      inserted after a locked page are labelled `42A`, `42B`, … and later
      pages keep their original numbers. Research ▸ Script has separate
      Lock/Unlock Pages and Lock/Unlock Scenes Numbers controls. Stored as
      `scenario_data.scriptcraft_locked_pages`; KIT ignores it.
- [x] Header/footer revision labels and "Revised" title-page fields. Headers
      and footers support `{revision}`, `{date}` and `{page}`; an empty header
      gets a colour/date line when revision marks are exported. The title page
      gains a `REVISED` block, and FDX carries the same fields.
- [x] Import recoverable KIT revisions. Every non-empty saved version in
      KIT's `script_versions` table is parsed from its `<scenario>` XML and
      imported as a full revision baseline (idempotent, 24-set cap). FDX only
      stores current revision IDs, so prior text cannot be reconstructed;
      FDX revision import remains a documented limitation.
- [x] Large-script performance gate: revision diff < 8 ms for 500 pages
      (`five_hundred_page_diff_stays_under_eight_milliseconds`).

## Design constraints

- Do not require stable block IDs in `.kitsp`: KIT does not persist them.
  Baselines store element type + text and align scenes by heading.
- A revision stores its own full baseline. To compute marks, diff each
  baseline directly against the current script from oldest to newest; later
  colours overwrite earlier ones. This avoids chained false positives.
- Scene alignment: match headings, then trim common block prefix/suffix and
  run LCS on small middles (bounded DP). Large rewrites mark the whole changed
  scene. Removed baseline blocks are counted separately from changed blocks.
- Limit retained revisions (24) so the JSON row cannot grow without bound.
- Page locks never move script text. Anchors match by `kit_uuid` when
  available, then by type/text plus neighbouring lines; mid-block page starts
  match their paragraph. Deleted anchors are skipped, still locking the pages
  around them. Page labels live in the shared layout engine, so editor and
  PDF print the same `42A` labels and `{page}` header tokens.
- Revision colours: Blue, Pink, Yellow, Green, Goldenrod, Buff, Salmon,
  Cherry; cycle back to Blue. Marks are margin bars, not text colour, so
  light/dark themes stay readable.
- `.kitsp` remains canonical. A failure to parse revision JSON must never
  prevent opening the script.
