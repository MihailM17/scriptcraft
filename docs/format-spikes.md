# Format spikes

This file records the exact on-disk shapes we need for v0.8 features. Do not
guess a format from documentation alone: create a minimal file in the real
application, inspect it, and record what the app actually writes.

## Rules

- Use only files we have the right to inspect and redistribute.
- Record the application and version used to create the sample.
- Keep the smallest possible fixture: one scene, one dialogue pair, one omitted
  scene, one revision.
- Add the fixture to `fixtures/real/` only with a provenance note.
- If a format cannot represent a feature, write that down. A documented loss is
  better than a silent one.

## Spike 1 — Omitted scenes

Questions:

- How does Final Draft write an omitted scene in `.fdx`? Which element or
  attribute carries the state?
- How does KIT Scenarist represent an omitted scene in `.kitsp`? Is it a scene
  heading rewrite, a `scenario_data` row, or nothing at all?
- Does an omitted scene keep its number, its page starts and its revision
  colour on export?
- What happens to the body text: retained but hidden, or removed?

Sample: `fixtures/real/omitted-scene.fdx` + `fixtures/real/omitted-scene.kitsp`.

Findings (2026-10-28):

- FDX (documented, not yet fixture-verified): Final Draft's own knowledge base
  says **Production → Omit Scene** replaces the scene heading text with
  “OMITTED”, keeps the scene number, hides the body, and marks the omission as
  a revision when revision mode is active
  (<https://kb.finaldraft.com/hc/en-us/articles/27810683389460-How-do-I-omit-a-scene>).
  The public FDX Conformance feature list independently describes
  “OMITTED scenes with `Length="0"`”
  (<https://www.tryarqo.com/fdx-conformance>). A synthetic sample generated by
  Inkwell's browser FDX inspector uses:
  `<Paragraph Type="Scene Heading"><SceneProperties Number="3" Locked="Yes" Length="0" /><Text>OMITTED</Text></Paragraph>`.
  The conformance corpus itself is proprietary, and the Inkwell sample is
  synthetic, so this is **not** yet evidence of what Final Draft actually
  writes for the body, revision marks, page starts or round-trip. Do not
  implement FDX omission from these references alone.
- KIT (source audit): KIT Scenarist 0.7.2 (rc15) was inspected at
  `/Applications/Scenarist.app`; the upstream source was cloned and searched.
  No omitted/omit handling exists outside bundled third-party libraries. KIT
  appears to have no native omitted-scene representation, so ScriptCraft must
  keep omission in its own sidecar row and warn on KIT export.
- Decision for ScriptCraft: use the versioned sidecar (`SceneMeta.omitted`) as
  the canonical representation for KIT projects. Keep the FDX mapping behind a
  real Final Draft fixture. Until that fixture exists, FDX export reports the
  omission as unsupported rather than inventing an attribute.

## Spike 2 — Dual dialogue

Questions:

- How does Final Draft group two consecutive dialogues into a dual pair in
  `.fdx`? Which wrapper, attribute or paragraph property?
- How does KIT store the pairing in `.kitsp`?
- What happens to `(CONT'D)`, parentheticals and page breaks inside a pair?
- Does the pairing survive a `.fdx` round-trip through Final Draft?

Sample: `fixtures/dual-dialogue.fdx` (synthesized from the exact shape used by
the Final Draft templates bundled with KIT; not a real-production fixture).

Findings (2026-11-04):

- FDX: a dual pair is one wrapper paragraph whose child list is two dialogue
  columns:

  ```xml
  <Paragraph Type="General">
    <DualDialogue>
      <Paragraph Type="Character"><Text>ADA</Text></Paragraph>
      <Paragraph Type="Parenthetical"><Text>(quietly)</Text></Paragraph>
      <Paragraph Type="Dialogue"><Text>It is still moving.</Text></Paragraph>
      <Paragraph Type="Character"><Text>GRACE</Text></Paragraph>
      <Paragraph Type="Dialogue"><Text>Then we stop it together.</Text></Paragraph>
    </DualDialogue>
  </Paragraph>
  ```

  The wrapper is `Type="General"`; each column starts with a `Character`
  paragraph and may include `Parenthetical` and `Dialogue` paragraphs. The
  examined Final Draft templates (KIT's `other/Final Draft templates`, fd9 and
  fd10) always contain exactly two columns. Character names may already carry
  `(CONT'D)`; dialogue text can be split across multiple `<Text>` runs.
  No wrapper-level attribute identifies the pair.
- KIT: no dual-dialogue representation. Searching KIT Scenarist 0.7.2 rc15
  source and UI found no `DualDialogue` reader/writer and no pairing command;
  the only occurrences are inside the bundled Final Draft templates. A KIT
  import therefore sees the wrapper as an empty `General` paragraph and the
  two columns as ordinary consecutive dialogue; the pairing is lost. KIT must
  not be treated as a round-trip carrier for dual dialogue.
- Decision for ScriptCraft: store the pairing in a versioned
  `scenario_data.scriptcraft_dual_groups` sidecar keyed by the two stable
  character-block IDs. KIT ignores the row and still edits the script text
  normally; reopening in ScriptCraft restores the pairing when both IDs still
  resolve to adjacent character/dialogue units. FDX import/export maps the
  sidecar to the `<DualDialogue>` wrapper above. Fountain export keeps the text
  and reports that pairing is not represented. KIT save warns that KIT will
  show the pair as ordinary dialogue.
