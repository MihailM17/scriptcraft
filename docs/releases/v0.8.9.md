# ScriptCraft v0.8.9

Released: 2026-11-19

> macOS DMG in this release is **ad-hoc signed** (no Developer ID/notarisation).
> Windows/Linux artifacts are unsigned. The in-app installer verifies the
> download and replaces the app, but it cannot bypass Gatekeeper/SmartScreen
> until those builds are signed. This is not a silent updater and not a
> notarised distribution.

> **Correction (v0.8.10).** The bold-body change below did not match KIT.
> KIT's rendered pages set the script body in regular Courier New and bold only
> the title-page title and page numbers. v0.8.10 reverts the body to regular;
> the section is kept as a record of what v0.8.9 shipped.

## Highlights

v0.8.9 makes the printed page match KIT Scenarist's actual output, adds Fade In
import/export and Markdown export, and ships a public website.

### The PDF prints in bold, like KIT Scenarist

> Superseded by v0.8.10: the body is regular in KIT's printed pages.

KIT Scenarist's Final Draft A4 template stores `bold="false"` on every style,
yet the PDF it prints embeds `CourierNewPS-BoldMT` and renders the whole body
in bold. ScriptCraft now matches the printed page:

- **Body text is bold.** Scene headings, action, character cues, parentheticals,
  dialogue, lyrics, transitions, `(MORE)`, `(CONT'D)` and shot lines are set in
  the bundled **Courier Prime Bold**. Page numbers stay bold; the running
  header and footer stay regular.
- **Dual dialogue is bold in both columns.** Each half of a dual-dialogue pair
  is printed in bold, matching KIT's side-by-side page.
- **The editor stays regular.** KIT's own editor shows regular text, and the
  bold face shares Courier Prime's advance width, so pagination and line breaks
  do not change. The editor/PDF parity test still compares the two page by page.
- **One switch.** `BODY_BOLD` in `scriptcraft-layout/src/pdf.rs` controls the
  policy; a test pins the PDF and editor layouts together.

### Fade In import and export

`.fadein` is a ZIP archive whose `document.xml` is an Open Screenplay Format
document. Both directions now work:

- **Import.** Reads `<document>` → `<paragraphs>`, maps `basestylename` (and
  early OSF `basestyle`) to ScriptCraft element types, restores scene numbers
  from `<para number="…">`, rebuilds dual-dialogue pairs from the
  `dualdialogue="1"` flag on the left cue, turns `<para note="…">` into
  non-printing notes, and reads the title page bookmarks (`Title`, `Credit`,
  `Author`, `Source`, `Draft`, `Contact`).
- **Export.** Writes a real ZIP containing one deflated `document.xml` with
  A4 settings, the standard style table, scene numbers on every heading,
  title-page bookmarks, notes and the dual-dialogue flag. Parentheticals are
  written without their outer parentheses, as Fade In stores them, and wrapped
  again on import.
- **Small ZIP helper.** The reader/writer handles the one entry it needs
  (stored or deflated, CRC-checked, no ZIP64) with `flate2` and `crc32fast`
  rather than a general-purpose ZIP dependency.
- **Dual dialogue is native.** The export status line no longer warns about
  dual pairs for Fade In.

### Markdown export

A clean one-way copy for notes, wikis and review:

- Title page fields become a heading and metadata lines.
- Scene headings, cast lists and character cues are bold; parentheticals,
  transitions and lyrics are italic; notes become `> **Note:**` blockquotes.
- Markdown that would change the script is escaped, so an action line beginning
  `#` or `-` still reads as an action line.
- Markdown has no pairing syntax: dual pairs export as consecutive dialogue and
  the status line says so.

### Website

`website/` is a static, dependency-free site (system fonts, automatic
light/dark, a persisted theme toggle) with feature cards, a format table,
screenshots from the real app, download cards and an FAQ. It is published by
`.github/workflows/pages.yml` to GitHub Pages on every push that touches it.

The FAQ states the bold-PDF behaviour and the unsigned-build caveat in plain
words.

## Verification

- **Bold PDF (superseded by v0.8.10):** `scriptcraft-layout` PDF tests,
  including `a95_pdf_matches_editor_layout`, plus the updated parity fixture.
  This assertion was reverted in v0.8.10 because KIT prints a regular body.
- **Fade In:** `round_trip_preserves_blocks_and_parentheticals`,
  `exports_scene_numbers_and_locks_them_on_import`,
  `dual_dialogue_round_trips_through_the_left_cue_flag`,
  `notes_stay_notes_and_do_not_print_as_body_text`,
  `accepts_basestyle_from_early_osf_documents`,
  `wrapping_parentheticals_matches_the_storage_convention`,
  `rejects_non_fadein_input` and `zip_entries_are_deterministic`; the
  interaction test `fadein_import_builds_a_project_with_dual_dialogue` runs a
  real archive through the app, and `import_menu_offers_fade_in` checks the
  menu entry.
- **Markdown:** `renders_title_page_and_screenplay_structure`,
  `escapes_markdown_that_would_change_the_script` and
  `empty_project_still_produces_a_document`.
- **Export dialog:** `export_dialog_offers_fdx_not_docx` now checks the five
  format radios (PDF, FDX, Fountain, Fade In, Markdown) and that unused DOCX
  stays hidden. Snapshot `08_export_dialog` was regenerated for the extra row.
- Full workspace tests, clippy `-D warnings`, `cargo fmt --check`,
  `cargo deny check` and `git diff --check` pass before the release commit.

## Deferred

Markdown import (export is one-way), Fade In revision colours, Developer ID
signing and notarisation, Windows code signing, and root-causing the Linux
typing crash remain deferred.
